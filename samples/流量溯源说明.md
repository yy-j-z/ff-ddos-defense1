# 流量样本溯源说明（Traffic Provenance）

> 用途：答辩物证 + 评委问答底稿。证明 `samples/*.pcap` 是**自采真实业务流量**，非爬取、非玩具、可复现。

## 0. 一句话结论
`samples/` 下 7 个 pcap **不是从任何第三方网站或公开数据集"爬取"的**，而是用脚本对我们**自己部署的防御靶机（`defender:8080`）发起真实 HTTP 请求、由 `tcpdump` 在网卡层抓下的"自采真实业务流量"**。链路层字段（MAC 地址 / TTL / TCP 窗口）均为 Linux 协议栈真实值。

## 1. 为什么不是"爬取"
- **爬取** = 从外部站点 / 公开数据集下载他人流量。问题：① 有版权 / 合规风险；② 接口、UA、业务结构与本系统完全不匹配（等于拿别人的试卷考自己的学生）。
- **自采** = 脚本连接本系统 `defender`，发真实请求、收真实响应，`tcpdump` 抓真实包。流量天然对应本系统真实业务接口，是"自检系统测自己"的正确数据来源。

## 2. 生成方法（可审计 · 可复现 · 链路层真实）
- 抓包工具：`tcpdump` 4.99.5（容器内 `apt-get install tcpdump`）
- 脚本：`samples/capture_real_traffic.py`（NO_WPCAP 模式：只发真实流量，不写文件，由 tcpdump 负责记录）
- 原理：真实 TCP socket 连 `defender:8080` 发真实 HTTP 请求（方法/路径/UA 取自业务画像），接收真实响应；`mixed-protocol` 场景用 scapy 补真实 UDP/DNS/ICMP 探测。`tcpdump -i any` 抓 `host defender`（172.18.0.2）的全部真实包。
- 复现命令（现场可当着评委面重跑）：
  ```bash
  docker cp samples/capture_real_traffic.py ff-attacker-worker:/tmp/
  docker exec ff-attacker-worker bash -c 'for sc in ecommerce api-gateway login-heavy mixed-protocol file-upload websocket api-concurrency; do
    tcpdump -i any -w /tmp/$sc.pcap "host 172.18.0.2" >/dev/null 2>&1 & TPID=$!
    sleep 1
    SCENARIO=$sc NO_WPCAP=1 python /tmp/capture_real_traffic.py
    sleep 1; kill $TPID
  done'
  docker cp ff-attacker-worker:/tmp/*.pcap samples/
  ```
- 重跑后新 pcap 当场生成，analyzer 当场解析出对应画像 → **可复现即不可造假**。

## 2.1 离线兜底脚本（Docker 不可用时仍可复现）
- 文件：`samples/capture_offline.py`（**纯标准库，零依赖，不装 scapy、不依赖 Docker**）。
- 用途：现场若 Docker 起不来、无法在容器内 tcpdump 重跑，用任意一台笔记本 + 任意可达 HTTP 服务即可重新生成 PCAP，证明"抓包流水线"本身可运行、可复现。
  ```bash
  # 纯离线：本地起一个 http 服务即可演示
  python -m http.server 8099 &
  python capture_offline.py --host 127.0.0.1 --port 8099 --all --out ./samples
  ```
- 诚实声明：离线脚本生成的 PCAP **链路层为合成**（离线无真实网卡），仅作"方法可复现"的兜底演示；**生产级样本仍以容器内 tcpdump 真抓为准**（见第 6 节指纹）。两者脚本同源、场景定义一致，保证可复现。

## 3. 样本与业务画像对应（实测，证明"流量贴本系统"）
| 样本 | 包数 | 主打接口（实测 top） | 协议构成 | UA 多样性 |

## 4. 为何不用公开 DDoS 数据集（CIC-DDoS2019 / CAIDA 等）
公开数据集是他人网络中的**攻击**流量，业务结构不匹配。本系统的价值在于"验证防御器对自己业务接口的防护效果"，自采流量是唯一正确选择——测的是自己的靶，得出的分数才对自己的系统有意义。

## 5. 诚实声明
- 原合成样本（`gen_samples.py` 生成）未删除，备份在 `samples/synthetic-backup/`，证明我们确实做了替换、态度透明。
- 流量内容（请求 / 响应 / 接口 / UA / 协议）100% 真实；本次升级后**封装层（MAC/TTL/窗口）也由 tcpdump 真抓**，不是脚本构造的默认值。

## 7. 评委高频追问 · 标准应答
**Q：这些流量包是从哪爬取的？**
A：不是爬取，是自采。我们对自己部署的防御靶机发真实请求、tcpdump 在网卡层真抓，流量天然对应我们真实业务接口。爬第三方数据集才有合规风险且接口不匹配。

**Q：这包是真的还是造的？**
A：请求/响应/接口/UA/协议 100% 真实，链路层 MAC/TTL/窗口也是 Linux 协议栈真值（tcpdump 真抓，非构造）。Wireshark 可验证三次握手。

**Q：为什么不用公开 DDoS 数据集？**
A：那些是别人网络的攻击流量，接口结构跟我们系统不一样。自采流量才能保证测的是"防御器对自己业务接口的防护"，这才是本系统的意义。

**Q：怎么证明不是提前编好的？**
A：三件套——① 抓包脚本 `capture_real_traffic.py` 在场可审计；② 原合成样本备份在 `synthetic-backup/`（态度透明）；③ 现场可重跑脚本当场生成新 pcap、analyzer 当场解析。

**Q：现场 Docker 起不来，你说的"重跑"不就废了？**
A：准备了零依赖离线脚本 `capture_offline.py`（纯标准库、不装 scapy、不依赖 Docker）。即使 Docker 不可用，在一台普通笔记本上对任何可达 HTTP 服务（包括本地 `python -m http.server`）即可重跑，当场产出 PCAP 证明流水线可复现。诚实讲：离线版链路层是合成的，生产样本仍以容器内 tcpdump 真抓为准——但"方法可复现"这一点不依赖 Docker。

**Q：就这几种流量？样本太少了吧？**
A：目前 7 类场景覆盖电商浏览、API 网关、登录密集、混合协议、文件上传、WebSocket 升级、API 高并发；每类都对应明确业务形态，analyzer 解析出的接口/UA/协议构成各不相同。场景定义写在脚本里，按需还能扩（如加 GraphQL、gRPC、视频流）。数量不在多，在于每类都有区分度、且可现场复现。
